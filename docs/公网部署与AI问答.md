# 字启千年：公网部署与 AI 问答

本轮把现有汉字学习作品补成“学习互动＋资料检索增强问答＋数据挖掘＋可视化分析”的完整流程。公网版本由一个 Node 服务同时提供网页和问答 API，访客打开网页即可提问。项目仍可双击 `index.html` 离线体验七个学习模块。

## 这次增加了什么

| 能力 | 实际实现 | 演示方式 |
| --- | --- | --- |
| DeepSeek 汉字问答 | 服务端调用；Key 从环境变量读取；访客无需 Key | 01 → AI 汉字问答 |
| 资料检索增强 | 从当前字、问题提及的字、分类和关联字中检索，最多六张汉字卡；统计问题另取同源摘要 | 问“比较「休」和「明」的构件” |
| 多轮追问 | 最近三轮对话参与理解，每轮重新检索；画面最多保留八轮，换字清空 | 继续问“它们共享构件吗？” |
| 依据展示 | 每轮列出资料编号与全文，可以展开核对、跳到字源或看板 | 展开 [S1] 资料卡 |
| 高频构件挖掘 | 在当前筛选切片中统计现代构件；同一字重复出现的构件只计一次 | 07 → 点“木”，查看对应字族 |
| 构件相似推荐 | 采用保留重复次数的多重集合 Jaccard，相同字不推荐给自己 | 从“林”比较“森”及其他字 |
| 共现关联规则 | 计算支持度、置信度、提升度；默认至少两字共现、置信度至少 50%；允许切换到一字探索 | 切换最少共现阈值，查看样本汉字 |
| 大屏展示与导出 | 原覆盖点阵和缺口明细保留；新增全屏展示、当前切片分析 CSV | 07 → 全屏展示／导出分析 CSV |

当前全量目录 134 字，其中 **38 条**具有可分析的合体构件；构件“木”出现于其中 **10 字**。这两个数字每次从目录计算。独体字、没有细拆的记录不放进挖掘分母。当前两字阈值下没有合格的构件对规则，界面如实显示空结果；一字探索中的高置信度仅描述该小样本。构件“亻”与“人”按目录原样区分，没有未经依据的合并。

问答检索是适合小型资料库的汉字提及、分类匹配及关联扩展；模型负责组织解释。古文字缺格、逐格来源和独立查询例证的边界均随资料卡发送。编号表表示“本次检索到的依据”，模型生成的内容仍需核对。没有加入模型训练或字形识别。

## 本机启动

需要 Node.js 22.9 或更新版本，无第三方服务端依赖，不需要执行 `npm install`。

在工程根目录运行：

```powershell
Copy-Item .env.example .env
```

用编辑器填写 `.env` 中的 `DEEPSEEK_API_KEY`，然后：

```powershell
npm start
```

打开 <http://127.0.0.1:4173>，进入“01 汉字探索 → AI 汉字问答”。Key 留在 `.env`，不需要填进网页或发到聊天中。没有 Key 时，页面会显示问答暂未开放，资料卡和其他学习功能照常可用。

默认调用 `https://api.deepseek.com/chat/completions`，模型默认 `deepseek-flash`，可以通过 `DEEPSEEK_MODEL` 改成账号支持的模型。当前模型名与请求格式已对照 [DeepSeek 官方首次调用说明](https://api-docs.deepseek.com/) 和 [Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/) 核对；采用非流式回答、关闭思考模式、最多 1024 输出 token。

## Docker 部署

在安装了 Docker 的机器、解压后的部署目录中执行：

```sh
docker build -t ziqi-millennium .
docker run -d --name ziqi-millennium --restart unless-stopped --env-file .env -e HOST=0.0.0.0 -p 127.0.0.1:4173:4173 ziqi-millennium
```

`.env` 放在运行机器上，镜像构建不会包含它。容器使用非 root 用户，健康检查检测网页服务是否正常；健康检查成功不等于 DeepSeek 账号可用。当前工作环境没有 Docker，因此尚未执行镜像构建或容器运行验证。

公网发布时，用 HTTPS 反向代理把同一个域名转发到 `127.0.0.1:4173`，并把 `PUBLIC_ORIGIN` 设置成实际地址，例如 `https://your-domain.example`。前端使用相对地址 `/api/health` 和 `/api/ask`，不需要另配跨域接口。托管平台则设置 `HOST=0.0.0.0`、`DEEPSEEK_API_KEY` 和 `PUBLIC_ORIGIN`，启动命令使用 `npm start`，端口可由平台通过 `PORT` 注入。

同一个域名需要同时代理静态文件和 `/api/`。只上传到 GitHub Pages、Gitee Pages 等静态托管不能运行问答后端。若已有静态托管，需要给同域 `/api/` 配置反向代理，或把整包放到支持 Node／容器的平台。

反向代理的必要设置示例（域名和 HTTPS 证书由实际平台配置）：

```nginx
location / {
    proxy_pass http://127.0.0.1:4173;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_read_timeout 60s;
}
```

只有在应用端口无法被外部直连、且代理会覆盖 `X-Forwarded-For` 时，才设置 `TRUST_PROXY=true`。默认不信任该请求头；此时同一个反向代理后的访问会共享其地址的频率限制。

## 请求与费用控制

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 服务端密钥；未配置不调用模型 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 服务端决定模型，访客不能覆盖 |
| `ASK_RATE_LIMIT` | 8 | 每个地址每分钟最多八次模型请求 |
| `ASK_DAILY_LIMIT` | 200 | 单进程每日模型请求上限，失败调用也计入 |
| `ASK_CONCURRENCY` | 4 | 全站并发上限；同一地址同时只处理一次 |
| `ASK_TIMEOUT_MS` | 40000 | 上游请求超时，取消会释放并发占用 |
| `PUBLIC_ORIGIN` | 空 | 公网时设置本站 HTTPS origin |
| `TRUST_PROXY` | `false` | 是否使用可信代理覆盖后的地址 |

问题限制 300 字，历史最多三轮，请求体有大小限制。服务器重新构造系统规约与资料卡，拒绝客户端传入模型、密钥、服务地址或自定义系统消息。静态服务只开放 `index.html`、`assets/`、`data/`、`src/` 的允许格式，`.env`、Git 配置、服务端源码不通过网页提供。

限流和日配额是单进程内存计数，按 UTC 日界重置，重启会清空；该部署包适合单实例演示和小流量使用。需要多实例或严格的跨重启费用上限时，应使用托管网关／共享计数器。本站服务不记录提问、回答或 Key；网络请求由 DeepSeek 处理，其数据规则以服务商现行条款为准。

访客界面只保留提问、追问与参考资料，不再提供连接设置、个人 Key 或模型选择。部署者通过服务器环境变量配置模型；双击离线文件时仍可阅读资料和使用七个学习模块，在线问答需通过 Node 服务或部署后的网址访问。

## 向指导老师演示

建议四分钟流程：

1. 用“休”展示书写、古今演变与构形互动，说明内容已有结构化资料支撑。
2. 打开 AI 问答，问“比较「休」和「明」的构件”，接着追问“它们共享构件吗？”，展开资料编号核对。
3. 在 07 看板进入全屏，查看语料覆盖与缺口；点“木”看十个相关合体记录，再切换“林”的构件相似推荐。
4. 切换共现阈值，解释小样本限制；导出当前切片 CSV，展示分析结果可以继续用于复核。

可以这样回复老师：

> 已在原来的汉字展示和互动学习基础上，补充了语料可视化看板、构件频次与相似度分析，以及 DeepSeek 资料问答。问答会检索项目中的字义、构件和逐期字形来源，支持多轮比较与追问，并展示依据。分析结果可以筛选、下钻到具体汉字和导出，形成“资料整理—分析发现—智能解释—互动学习”的流程。
